# Implementation Notes

Create an implementation note only when a change has non-obvious migration, operational, compatibility or developer guidance that does not belong in an existing canonical architecture, ADR or runbook.

Naming:

`IMP-<requirement-id>-<short-name>.md`

Recommended sections:

- Requirement/design references
- Changed modules
- Implementation decisions within the approved design
- Migration or compatibility notes
- Execution command
- Developer verification
- Test Engineer handoff
- Known risks

Do not use implementation notes as a second Source of Truth for architecture or requirements.
